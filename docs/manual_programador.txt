1. VISION GENERAL DEL SISTEMA
================================================================================

SuColor Pro es una aplicacion web de gestion integral para talleres de pintura
automotriz. Permite administrar el ciclo de vida completo de un vehiculo en
taller, desde su ingreso hasta su entrega.

FUNCIONALIDADES PRINCIPALES:
  - Gestion de ordenes de trabajo con tablero Kanban
  - Administracion de clientes y vehiculos
  - Galeria multimedia (fotos antes/proceso/despues)
  - Control de pagos y gastos por orden
  - Facturacion electronica SRI (Ecuador)
  - Reportes de rentabilidad, garantias y estadisticas
  - Portal de seguimiento publico para clientes (sin login)

La aplicacion tiene DOS SUPERFICIES DE USUARIO diferenciadas:

  SUPERFICIE              URL BASE                 AUTENTICACION
  ---------------------------------------------------------------
  Portal cliente          /#/  y  /#/track/:codigo     Publica
  Panel administrativo    /#/administracion/*           Requiere login

4. CONFIGURACION DEL ENTORNO DE DESARROLLO
================================================================================

PRE-REQUISITOS:
  - Node.js >= 18.0 LTS
  - npm >= 9.0
  - Cuenta Supabase con proyecto configurado

PASOS DE INSTALACION:

PASO 1 - Clonar el repositorio:
  git clone <URL_REPOSITORIO>
  cd SuColor

PASO 2 - Instalar dependencias:
  npm install

PASO 3 - Configurar variables de entorno:
  cp .env.example .env
  (Editar .env con los valores reales - ver seccion 15)

PASO 4 - Configurar la base de datos:
  Ejecutar en el SQL Editor de Supabase Dashboard en este orden:

  1. supabase/migrations/20260509000001_secure_rls.sql
  2. supabase/migrations/20260727000000_secure_rls_admin_only.sql
  3. supabase/migrations/20260727000001_create_audit_log.sql
  4. supabase/setup_sri_invoicing.sql
  5. supabase/add_payment_columns.sql
  6. supabase/setup_admin_profile.sql

PASO 5 - Asignar rol admin al primer usuario:
  Ejecutar en Supabase SQL Editor:
  
  INSERT INTO public.user_roles (user_id, role)
  SELECT id, 'admin' FROM auth.users WHERE email = 'tu_email@dominio.com'
  ON CONFLICT DO NOTHING;

PASO 6 - Iniciar servidor de desarrollo:
  npm run dev

  La aplicacion estara disponible en: http://localhost:5173

ENUM OrderStatus - FLUJO DE ESTADOS:

  SECADO -> PULIDO_DETALLES -> TERMINADO -> ENTREGADO

Cada estado tiene colores, iconos y numero de paso configurados en:
  src/biblioteca/constantes.ts -> STATUS_CONFIG

TABLA user_roles (control de acceso):

  CREATE TABLE public.user_roles (
    id       UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id  UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    role     TEXT NOT NULL CHECK (role IN ('admin', 'viewer')),
    UNIQUE(user_id, role)
  );

  IMPORTANTE: Para que un usuario acceda al panel admin,
  debe tener un registro con role = 'admin' en esta tabla.

7. SEGURIDAD - ROW LEVEL SECURITY (RLS)
================================================================================

FUNCION is_admin():

  Todas las politicas administrativas usan esta funcion:

  CREATE OR REPLACE FUNCTION public.is_admin()
  RETURNS boolean
  LANGUAGE sql
  STABLE
  SECURITY DEFINER        -- Corre con permisos del owner (postgres)
  SET search_path = public -- Previene ataques de search_path hijacking
  AS $$
    SELECT EXISTS (
      SELECT 1 FROM public.user_roles
      WHERE user_id = auth.uid() AND role = 'admin'
    );
  $$;

POLITICAS POR TABLA:

  TABLA          SELECT       INSERT       UPDATE       DELETE
  ---------------------------------------------------------------
  ordenes        is_admin()   is_admin()   is_admin()   is_admin()
  clientes       is_admin()   is_admin()   is_admin()   is_admin()
  vehiculos      is_admin()   is_admin()   is_admin()   is_admin()
  media          is_admin()   is_admin()   is_admin()   is_admin()
  orden_gastos   is_admin()   is_admin()   is_admin()   is_admin()
  user_roles     user_id = auth.uid()    (solo lectura propia)

ACCESO PUBLICO (Tracking del cliente):

  El portal publico NO accede directamente a Supabase.
  Pasa por Supabase Edge Functions que validan el codigo/token
  antes de retornar datos filtrados al cliente.

TABLA rate_limits (control de tasa en Edge Functions):

  CREATE TABLE public.rate_limits (
    ip           TEXT NOT NULL,
    endpoint     TEXT NOT NULL,
    window_start TIMESTAMPTZ DEFAULT date_trunc('hour', now()),
    count        INTEGER DEFAULT 1,
    UNIQUE(ip, endpoint, window_start)
  );

8. SISTEMA DE ENRUTAMIENTO
================================================================================

Se usa HashRouter (#-based routing) para compatibilidad con hosting
estatico sin configuracion del servidor web.

RUTAS PUBLICAS:
  /                          -> PaginaInicio
  /track/:codigo             -> PaginaSeguimiento

RUTAS ADMINISTRATIVAS (protegidas por RutaProtegida HOC):
  /administracion/login          -> PaginaInicioSesion
  /administracion/dashboard      -> PaginaPanel
  /administracion/orders         -> PaginaListaOrdenes
  /administracion/orders/nueva   -> PaginaNuevaOrden
  /administracion/orders/:id     -> PaginaDetalleOrden
  /administracion/clientes       -> PaginaClientes
  /administracion/vehiculos      -> PaginaVehiculos
  /administracion/reportes       -> PaginaReportes
  /administracion/configuracion  -> PaginaConfiguracion

REDIRECCIONES:
  /admin   -> redirige a /administracion/orders
  /*       -> pagina 404 (NotFound)

COMPONENTE RutaProtegida:
  HOC que verifica sesion activa con Supabase Auth.
  Si no hay usuario autenticado, redirige automaticamente
  a /administracion/login.

10. GANCHOS PERSONALIZADOS (CUSTOM HOOKS)
================================================================================

Todos los ganchos estan en: src/ganchos/
Encapsulan la logica de negocio y el estado, manteniendo los
componentes como vistas puras.

--- useAutenticacion ---

  Firma:
    function useAutenticacion(): {
      user: { id: string; email?: string } | null;
      loading: boolean;
      error: string | null;
      login: (email: string, password: string) => Promise<boolean>;
      logout: () => Promise<void>;
    }

  Notas:
    - Suscripcion reactiva a supabase.auth.onAuthStateChange
    - Persiste la sesion automaticamente (JWT en localStorage)

--- useBusquedaOrden ---

  Firma:
    function useBusquedaOrden(): {
      result: BusquedaOrdenResponse | null;
      loading: boolean;
      error: string | null;
      buscar: (query: string) => Promise<void>;
    }

  Notas:
    - Llama a la Edge Function para buscar por placa o codigo

--- useSeguimientoOrden ---

  Firma:
    function useSeguimientoOrden(codigo: string, token: string): {
      data: SeguimientoOrdenResponse | null;
      loading: boolean;
      error: string | null;
    }

  Notas:
    - Obtiene datos de orden para mostrar al cliente
    - Valida que el token coincida con share_token de la orden

--- useOrdenes ---

  Firma:
    function useOrdenes(filterEstado?: OrderStatus): {
      orders: AdminOrder[];
      loading: boolean;
      error: string | null;
      refetch: () => Promise<void>;
      updateEstado: (id: string, estado: OrderStatus) => Promise<boolean>;
      toggleShare: (id: string, enabled: boolean) => Promise<boolean>;
      deleteOrder: (id: string) => Promise<boolean>;
    }

  Estrategia de carga (3 pasos):
    1. Fetch de ordenes (sin join por restricciones de FK en RLS)
    2. Fetch en paralelo de clientes y vehiculos en lote (query IN)
    3. Fetch de foto de portada (categoria ANTES, primera creada)
    4. Merge en memoria para construir el array AdminOrder[]

--- useOrdenAdministracion ---

  Firma:
    function useOrdenAdministracion(id: string | undefined): {
      order: AdminOrder | null;
      loading: boolean;
      saving: boolean;
      error: string | null;
      precioTotal: number;
      montoPagado: number;
      setPrecioTotal: (v: number) => void;
      setMontoPagado: (v: number) => void;
      updateEstado: (estado: OrderStatus) => Promise<void>;
      toggleShare: () => Promise<void>;
      deleteOrder: () => Promise<boolean>;
      updateDetails: (updates: {...}) => Promise<void>;
      updateNotes: (notas: string | null) => Promise<void>;
      addNoteEntry: (entry: string) => Promise<void>;
      updatePaymentFields: (fields: {...}) => void;
    }

  Patron optimista:
    Las actualizaciones llaman a Supabase y si tienen exito,
    actualizan el estado local sin refrescar toda la orden:
    setOrder(prev => ({...prev, ...changes}))

  Feedback de audio:
    Cada accion exitosa reproduce un sonido diferente usando
    la Web Audio API desde src/biblioteca/sonidos.ts

13. MODULO DE FACTURACION ELECTRONICA SRI
================================================================================

DESCRIPCION:
  SuColor Pro incluye soporte para emision de Facturas Electronicas SRI
  (Ecuador), cumpliendo con el esquema de comprobantes electronicos.

COMPONENTES INVOLUCRADOS:
  PanelPagos.tsx         -> Disparador del proceso de facturacion
  ModalFactura.tsx       -> Formulario completo de datos de factura
  PaginaConfiguracion.tsx -> Config empresa, RUC, certificado P12

FLUJO COMPLETO DE FACTURACION:

  PASO 1: Admin presiona "Emitir Factura" en PanelPagos
          |
          v
  PASO 2: Se abre ModalFactura con datos pre-llenados de la orden
          |
          v
  PASO 3: Admin revisa/ajusta items, aplica IVA 15% o 0%
          |
          v
  PASO 4: ec-sri-invoice-signer genera el XML del comprobante
          |
          v
  PASO 5: El XML se firma digitalmente con certificado P12
          (almacenado en Supabase Storage bucket 'firmas')
          |
          v
  PASO 6: El XML firmado se envia al SRI
          (ambiente pruebas o produccion segun config)
          |
          v
  PASO 7: SRI retorna autorizacion / mensajes de error
          |
          v
  PASO 8: Estado de Invoice se actualiza en base de datos:
          CREADA -> FIRMADA -> RECIBIDA -> AUTORIZADA (o RECHAZADA)

TIPOS DE IVA SOPORTADOS:

  codigo_porcentaje_iva    Tarifa
  ---------------------------------
  0                        0%
  2                        12%
  3                        14%
  4                        15% (vigente 2024+)

CONFIGURACION REQUERIDA (PaginaConfiguracion):
  - RUC y Razon Social
  - Direccion Matriz
  - Establecimiento (ej: 001) y Punto de Emision (ej: 001)
  - Secuencial inicial (ej: 00000001)
  - Certificado P12 (archivo .p12 de firma electronica)
  - Contrasena del P12
  - Ambiente: 1 = Pruebas, 2 = Produccion

ESTADO DE LA FACTURA EN BD:
  estado: 'CREADA' | 'FIRMADA' | 'RECIBIDA' | 'AUTORIZADA' | 'RECHAZADA'
  ambiente: 1 (pruebas) | 2 (produccion)

PATRON ESTANDAR PARA UN HOOK:

  export function useMiGancho(parametro: string) {
    const [data, setData] = useState<TipoDato | null>(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState<string | null>(null);

    useEffect(() => {
      if (!parametro) return;
      const cargar = async () => {
        setLoading(true);
        setError(null);
        try {
          const { data, error } = await supabase.from('tabla').select('*');
          if (error) throw error;
          setData(data);
        } catch (e) {
          setError('Mensaje de error amigable');
        } finally {
          setLoading(false);
        }
      };
      cargar();
    }, [parametro]);

    return { data, loading, error };
  }

20. PREGUNTAS FRECUENTES DEL DESARROLLADOR
================================================================================

P: Por que se usa HashRouter en vez de BrowserRouter?
R: Porque la app se despliega en hosting estatico. Con BrowserRouter,
   recargar la pagina en /administracion/orders/123 daria un 404.
   Con HashRouter, el servidor siempre recibe index.html y el router
   lo maneja completamente en el cliente.

P: Por que las queries a Supabase no usan joins directos como
   .select('*, clientes(*)')?
R: Por las politicas RLS. Los joins en Supabase requieren que el
   cliente tenga permiso explicito sobre la tabla referenciada.
   Para evitar errores de FK constraint con RLS, se hacen queries
   separados y el merge se hace en memoria dentro de los ganchos.

P: Como agrego un nuevo estado de orden?
R: 1. Agregar el valor al enum public.orden_estado en PostgreSQL
   2. Agregar el tipo en src/tipos/index.ts -> OrderStatus
   3. Agregar la configuracion visual en
      src/biblioteca/constantes.ts -> STATUS_CONFIG
   4. Si corresponde, agregarlo a PROGRESS_STEPS

P: Como agrego un nuevo reporte?
R: 1. Crear el componente en:
      src/componentes/administracion/reportes/ReporteNuevo.tsx
   2. Usar <EncabezadoImpresion> al inicio del componente
   3. Importarlo en:
      src/paginas/administracion/PaginaReportes.tsx
   4. Anadirlo al selector de reportes de esa pagina

P: Por que el cliente Supabase usa un placeholder en vez de lanzar
   un error cuando no estan las variables de entorno?
R: Para no crashear el proceso de build en CI/CD donde las variables
   de produccion no estan disponibles. El cliente placeholder falla
   silenciosamente en todas las llamadas, lo cual es aceptable en
   un entorno de build sin BD real.

P: Como funciona el sistema de roles de admin?
R: El JWT de Supabase solo identifica al usuario. La funcion
   is_admin() consulta la tabla user_roles en la BD.
   Para agregar un nuevo administrador, ejecutar en SQL:

   INSERT INTO public.user_roles (user_id, role)
   VALUES ('<uuid-del-usuario>', 'admin');

P: Donde se almacenan los certificados P12 de firma electronica?
R: En el bucket 'firmas' de Supabase Storage, con acceso restringido
   solo a usuarios autenticados.
   La ruta del archivo se guarda en:
   company_settings.p12_storage_path
